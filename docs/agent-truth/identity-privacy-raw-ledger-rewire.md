# Identity, Privacy, And Raw Ledger Rewire

Status: static foundation contract for analytics rewire Prompt 2

## Purpose

Prompt 2 exists to make later analytics recovery safe before runtime refactors begin. KandyDrops may already have useful guest, session, journey, watch, support, purchase, unlock, notification, and legacy data, but future recovery must not mix actor lanes, revive denied-consent behavior, or treat pseudonymous ids as anonymous.

The report is generated by:

```bash
npm run check:identity-privacy-raw-ledger-rewire
```

The generated snapshot is:

```text
agent/state/identity-privacy-raw-ledger-rewire.generated.json
```

## Identity Actor Lanes

Analytics actor lanes must stay separate:

- guest
- anonymous_visitor
- session
- authenticated_user
- creator
- admin
- system
- unknown

Target fields do not define actor identity. For example, `target_creator_id` or `targetCreatorId` does not mean the actor is a creator. Admin/system events are excluded from ordinary user and guest behavior by default unless a module explicitly compares lanes with a visible label. Creator operations stay separate from fan/user behavior unless a module explicitly compares creator/fan lanes.

Identity links such as `identity_linked` and `analytics_identity_links` add relationship evidence. They must preserve guest/session lineage and must not rewrite old guest facts into authenticated-user facts.

## Pseudonymous Identifiers

`subject_*`, `anon_*`, `sessionId`, `anonymousVisitorId`, and `kandy_session_id` are pseudonymous identifiers, not fully anonymous data, unless a stronger anonymization contract is proven. They can help recover continuity, but they must remain consent-aware and purpose-labeled.

Guest-to-user continuity must not revive denied-consent behavior into ordinary analytics.

## Privacy-Off Measurement Modes

Privacy-off is neither `collect nothing` nor `collect everything`. It uses three distinct modes.

### required_operational

Allowed when privacy settings are off when necessary for service, security, payment, unlock, support, or legal integrity.

Requirements:

- first-party first
- minimized payload
- retention-limited
- purpose-labeled
- no ads or marketing personalization

Examples:

- payment/refill integrity
- unlock/entitlement integrity
- abuse/security/rate limit
- error diagnostics
- support recovery
- consent records

### limited_consent_off_measurement

Allowed only if configured to meet applicable consent-exemption rules.

Requirements:

- first-party or publisher-only
- aggregate or minimized measurement
- no cross-site tracking
- no ads or marketing personalization
- no identity-tied session replay
- documented opt-out/consent policy where applicable

Examples:

- aggregate performance
- navigation issue detection
- capacity or technical optimization

### optional_analytics_personalization

Not allowed when privacy settings are off. This requires consent or opt-in.

Examples:

- optional GA4/PostHog analytics
- session replay
- personalization
- marketing-style behavioral tracking

## Raw ledger contract

The raw ledger is the first-party product behavior source, but raw rows are not final display metrics.

Required or strongly recommended fields include:

- `eventId`
- `eventName`
- `eventVersion` or `schemaVersion`
- `occurredAt`
- `receivedAt`
- `actorType`
- `anonymousVisitorId`
- `sessionId`
- `userId`
- `creatorId`
- `adminId`
- target/object fields
- `source`
- `consentState`
- `dedupeKey`
- `sourceConfidence` or reliability label
- `legacySource`, `legacyConfidence`, and `mappingWarnings` where recovered

Raw event counts must not be treated as unique users, ordered funnels, bounces, live presence, purchases, unlocks, or launch readiness without a snapshot/index contract.

## Recovery eligibility

Recovery candidates are classified before any production backfill.

The report decides whether each lane is:

- Admin Analytics eligible now
- Debug-only first
- consent required
- eligible only when minimized
- required operational only
- future dry-run backfill eligible
- needs identity graph continuity first
- not eligible under denied-consent conditions

High-value recovery candidates must go through Admin Debug evidence before compact Admin Analytics display.

## Future Use

Future phases should use this report to:

- decide which identity keys can join guest/session/user facts
- decide what can be surfaced in Admin Analytics
- decide what stays Debug-only
- add dry-run recovery mappers
- lock runtime raw ledger fields in narrow follow-up patches
- prevent optional analytics from running when privacy settings are off

## What This Report Must Not Be Used For

This report must not be used to:

- prove production data exists
- run a production backfill
- migrate or delete records
- alter runtime tracking behavior
- claim provider smoke passed
- claim screenshot QA passed
- mark missing data as zero
- mark stale data as live
- treat pseudonymous ids as anonymous
- override verified runtime code or higher-authority doctrine
