# Lost Data Recovery Dry Run

Status: static recovery planning contract for analytics rewire Prompt 3

## Purpose

This dry run exists because KandyDrops data may be unsurfaced rather than deleted. Data can be written to a raw ledger, a guest/session lane, a legacy field, an index, Debug-only evidence, a stale snapshot, or a vendor/export lane without becoming visible in Admin Analytics.

The report is generated by:

```bash
npm run check:lost-data-recovery-dry-run
```

The generated snapshot is:

```text
agent/state/lost-data-recovery-dry-run.generated.json
```

## What lost data Means

Lost data means recoverable evidence that may still exist but does not appear where operators expect it.

Examples include:

- written but not materialized
- materialized but not consumed
- consumed but filtered out
- shown only in Admin Debug
- stuck under guest, anonymous, session, or legacy identity keys
- excluded by actor classification
- hidden behind stale snapshots
- exported to GA4, PostHog, or BigQuery but not reconciled as first-party truth
- stored with legacy field names

## No Production Reads Or Backfill

This phase is static/local only. It must not run production reads, Firebase queries, BigQuery scans, GA4/PostHog calls, provider calls, production backfills, data migrations, or deletes.

All dry-run stages set `productionAllowedNow: false`.

## Recovery Lane Classification

Each lane is classified by:

- source path
- source type
- identity keys
- old fields
- canonical fields
- consent requirement
- Admin Debug eligibility
- Admin Analytics eligibility
- future backfill eligibility
- first surface target
- confidence
- recovery value
- cost risk
- blockers
- validators needed

## Debug-first Rule

High-value recovered data must surface in Admin Debug before Admin Analytics. Debug owns source paths, formulas, confidence, mapping warnings, stale states, missing samples, identity blockers, privacy blockers, and cost warnings.

Admin Analytics may consume recovered data only after Debug evidence proves the source is eligible, current enough, privacy-safe, and protected against fake zeros.

## Admin Analytics Surfacing Gate

Admin Analytics surfacing is allowed later only when:

- the lane is not Debug-only
- consent/privacy eligibility is proven
- actor identity is not mixed
- source truth beats vendor evidence
- fake-zero protection exists
- the value is materialized through a snapshot or declared index
- validators lock the source and fallback behavior

Raw event facts, guest batches, sessions, and legacy recovered events are not direct display truth.

## Privacy And Consent Eligibility

Privacy-off does not mean no operational data exists, and it does not allow all analytics. Recovery must use the Prompt 2 modes:

- `required_operational`
- `limited_consent_off_measurement`
- `optional_analytics_personalization`

Recovered identity keys such as `subject_*`, `anon_*`, `sessionId`, `anonymousVisitorId`, and `kandy_session_id` are pseudonymous. They must stay consent-aware and purpose-labeled.

Denied-consent behavior must not be revived into ordinary analytics.

## Dry-Run Backfill Stages

Stage A: static inventory of recoverable lanes.

Stage B: emulator-only mapper validation.

Stage C: dry-run recovery snapshot generation.

Stage D: Admin Debug surfacing.

Stage E: Admin Analytics surfacing only after Debug confidence.

Stage F: production backfill only after manual approval.

No stage permits production work in this prompt.

## Next Phase: Snapshot/Admin/Vendor/Cost Rewire

Phase 4 uses this dry-run report to decide how recovered lanes should move through snapshot authority, Admin Debug, Admin Analytics, and vendor evidence boundaries. It should keep high-value recovery Debug-first, make `analytics_admin_metric_snapshots` the recommended compact display authority, demote raw and vendor lanes to evidence/fallback roles, and record cost simplification candidates without changing runtime UI/routes.

## Future Phases

Next phases should:

- add emulator-only mapper fixtures
- build a Debug recovery evidence panel
- prove identity and consent eligibility per lane
- materialize dry-run recovery snapshots
- promote only eligible lanes into `analytics_admin_metric_snapshots`
- request manual approval before any production backfill

## What This Report Must Not Be Used For

This report must not be used to:

- claim production data was recovered
- read production Firebase
- query BigQuery
- call GA4, PostHog, or other providers
- backfill, migrate, or delete data
- change runtime tracking behavior
- change Admin Analytics or Admin Debug UI
- mark missing data as zero
- mark stale data as live
- treat vendor evidence as product truth
- bypass identity, consent, or privacy review
