# Analytics Module Map

Status: Phase 1 module inventory
Last updated: 2026-04-30

This map records the intended role, current source shape, desired source, snapshot needs, refresh behavior, debug parity, risks, and surface placement for Admin Analytics and Admin Debug modules.

## Module Snapshot Contract

Every module snapshot should eventually include:

- `selectedRange`
- `generatedAtMs`
- `lastValidatedAt`
- `sourceMode`
- `truthState`
- `cacheState`
- `refreshStatus`
- `serverConfirmed`
- `fromCache` and `hasPendingWrites` when Firestore listener data is used
- `fakeZeroPrevented`
- `legacyRecoveryUsed`
- `debugParityKey`
- module-specific formulas and denominators

## Placement Rule

Admin Analytics keeps compact operational insight modules. Admin Debug keeps long validation, source hierarchy, raw details, parity, recovery, and failure diagnostics. Modules with audit-only value should move to Debug instead of becoming giant Analytics card lists.
